# BSS_README

## 이론적 배경

본 데이터셋은 일본 만화 블리치의 쿠치키 뱌쿠야를 야니디스(Jannidis, 2013)의 개념인 ‘입체적 인물(Round Character)’로 이해한다. 입체적 인물은 단 하나의 관념이나 자질로 구축된 평면적 인물과 달리, 다층적인 내면 구조를 지니고 설득력 있는 방식으로 놀라움을 주는 인물을 뜻한다. 본 프로젝트는 독자가 원작을 수동적으로 읽는 데 머무르지 않고 능동적 대화 참여자(Active Conversational Participant)(박재영 외, 2024)가 되어, 멀티 턴(Multi-turn) 대화 속에서 뱌쿠야의 냉철한 태도 이면에 숨겨진 다면성과 고뇌를 직접 분석하고 입체적으로 이해하도록 설계되었다. 

본 데이터셋은 인물이 처한 상황을 ㉠ 딜레마와 행위자(bss:Dilemma, dm:hasDecisionMaker), ㉡ 상충하는 두 행동 선택지(bss:Option, dm:hasOption), ㉢ 행동의 근거가 되는 사건(bss:Event)과 규범적 가치(bss:Rule, bss:Value)로 나눈다. 본 데이터셋은 이 구분을 선택지(bss:Option)와 이를 지키거나 깨뜨리는 상충 관계(bss:upholds, bss:breaks)로 기록하였다. 뱌쿠야의 상충하는 두 선택지인 '루키아 구출 시도(bss:A00021)'와 '규율을 지킨다(bss:A00022)'를 분리하고, 부모 앞 맹세와 히사나와의 약속 같은 핵심 사건(bss:Event)을 bss:upholds와 bss:breaks로 대칭 연결하여 두 요구가 서로를 무효화하지 못하는 모순 구조를 드러냈다. 또한 두 가치가 대등하게 부딪치는 다면적 긴장을 보존하기 위해, 작중에서 실제로 택하지 않은 미선택 행위인 '루키아 구출 시도' 역시 데이터에 동등한 선택지(bss:Option)로 남겨 두었다.

이 관점에서 뱌쿠야의 갈등은 '가문의 규율'과 '아내와의 약속'이라는 양립 불가능한 가치가 맞부딪치는 내적 교착 상태로 읽힌다. 다만 온톨로지 데이터셋은 뱌쿠야가 결국 규율을 택했다는 정적인 사실 관계만 기록할 뿐, 인물이 겪는 심리적 동요나 실시간 고뇌의 과정까지 데이터 자체로 담아내지는 못한다. 또한 챗봇이 사용자의 질문이나 설득에 쉽게 넘어가 어느 한쪽을 대신 선택해 버리면 인물의 다면적 긴장감이 무너지므로, 챗봇은 미래 지식을 차단하고 어느 한쪽을 섣불리 결정해 주지 않은 채 고뇌와 모순의 상태를 유지하도록 설계하였다.

## 기대효과

### (1) 수동적 텍스트 소비를 넘어선 '능동적 딜레마 심층 분석'
기존의 만화 독해가 작가가 구성한 서사를 일방향으로 따라가는 수동적 읽기에 머물렀다면, 본 챗봇은 독자를 능동적 대화 참여자(Active Conversational Participant)로 전환시킨다. 독자는 뱌쿠야의 냉철한 태도 이면에 숨겨진 심리적 모순을 직접 질문하고 논박하는 분석 주체가 됨으로써, 겉으로 드러나지 않았던 인물의 다면적인 내적 갈등을 스스로 해체하고 비판적으로 분석하는 독해 경험을 얻을 수 있다.

### (2) 실시간 상호작용을 통한 '인물의 내적 갈등 간접 경험 및 이해 심화'
독자는 소울 소사이어티 편이라는 닫힌 시점의 가상 세계 속에서 '부모 앞의 맹세(공적 규율)'와 '망처 히사나와의 약속(사적 유대)'이 정면충돌하는 상황을 당사자와의 실시간 문답으로 마주한다. 이를 통해 인물이 겪는 선택의 무게와 심리적 압박감을 단순한 줄거리 파악을 넘어 생생하게 간접 경험하며, 뱌쿠야라는 다면적 캐릭터와 작품의 서사에 대한 이해를 한층 심화할 수 있다.

### (3) 인문 서사 데이터의 시맨틱 온톨로지 모델링과 생성형 AI의 결합 가능성 검증
인물의 주관적 고뇌와 선택 상황을 단순 요약에 그치지 않고, 딜레마(`bss:Dilemma`), 선택지(`bss:Option`), 사건(`bss:Event`), 규범과 가치(`bss:Rule`, `bss:Value`), 그리고 상충 관계(`bss:upholds`, `bss:breaks`)로 구조화된 RDF/TTL 온톨로지 데이터셋으로 정량화하였다.
정형화된 서사 지식 그래프와 프롬프트의 체계적 설정을 결합함으로써, 생성형 AI가 가상 인물을 재현할 때 발생하는 설정 왜곡과 환각을 억제하고 데이터에 기반한 일관된 페르소나 챗봇을 구축할 수 있음을 실증한다.

## 3. 프롬프트 설계

### (1) 프롬프트 변천표

| 차수 | 바꾼 점 | 바꾼 이유 (대화 시험에서 발견한 문제) |
| --- | --- | --- |
| 1차 | 뱌쿠야의 기본 역할과 루키아 구출 갈등, 작품을 읽은 독자와의 대화 규칙을 최초 설정함. | 독자가 인물의 내적 딜레마를 심층 분석하고 간접 경험하도록 하려는 초기 기획 의도를 구현하기 위함. |
| 2차 | 대화 공간을 '외부와 단절된 가상 공간'으로 한정하고, 딜레마의 양 축(규율 맹세 vs 아내 유언)을 구체화하며, 독자의 통찰에 '경계와 의구심을 품되 위엄을 지키라'는 규칙을 추가함. | |
| 3차 | 고풍스러운 귀족 어투(하오체/하게체), 짧은 문장 길이(2~5문장), 호칭("너", "네놈"), 점진적 개방(경계 ➔ 고뇌 ➔ 마음 엶), 모르는 정보 차단("알 필요 없다") 규칙을 추가함. | 대화에서 응답이 지나치게 길어져 현대적인 상담 챗봇처럼 장황하게 설명할 가능성을 차단함. |
| 4차 | 자연어 서술 지침을 4개 모듈(역할/기본 설정, 핵심 갈등, 사용자 관계 로직, 어조/출력 규칙) 마크다운 템플릿으로 구조화하고 제4의 벽 유지 지침을 명문화함. | LLM의 지시 준수율과 집중도를 높이기 위해 구조화함. |

## 4. 실행 설정

- 적용 모델: Gemini 3.8 Flash
- Temperature 설정값: 1.7
- 선정 이유: 높은 Temperature(1.7)를 설정함으로써 뱌쿠야가 정형화된 정답이나 기계적인 규칙 읊조림에 머무르지 않고, 독자의 다채로운 질문과 도발에 맞추어 생생하고 역동적인 어휘와 표현으로 내적 갈등을 표출하도록 유도하는 동시에, 경량화된 Flash 모델을 활용하여 실시간 멀티 턴 대화의 빠른 반응성과 인터랙티브한 대화 흐름을 확보하고자 하였다
